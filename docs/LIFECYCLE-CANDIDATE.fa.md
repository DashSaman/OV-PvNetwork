# نسخهٔ آزمایشی چرخهٔ مدیریت — PVN-1026 / 1.0.42

این نسخه هنوز ادغام و منتشر نشده است. نسخهٔ عمومی پایدار 1.0.37 و checkpoint عملیاتی مجاز 1.0.40 باقی می‌مانند.

Update فقط بستهٔ رسمی یک نسخهٔ ثابت و SHA256 همان فایل را می‌پذیرد. build و بررسی schema و canary پیش از تغییر نسخهٔ فعال انجام می‌شوند. سپس proxy پنل وارد maintenance می‌شود، نویسنده‌های متعلق به پنل متوقف می‌شوند، بکاپ نهایی گرفته می‌شود و اشاره‌گر برنامه به‌صورت اتمی تغییر می‌کند. پذیرش نصب قدیمیِ بدون symlink به `--adopt-rooted` صریح نیاز دارد. ابزارهای خصوصی و lockfile ثابت استفاده می‌شوند.

Backup از PostgreSQL با ابزار native و از SQLite با online snapshot گرفته می‌شود و بازیابی واقعی در دیتابیس یا فایل موقت انجام می‌شود. hash تمام ردیف‌ها، schema و فایل‌ها بررسی می‌شود. فایل‌های اعتماد SSH و کلیدهای رمزنگاری AnyConnect و push نیز پوشش دارند. بکاپ‌های مرتبط با تراکنش از retention محافظت می‌شوند. برای PostgreSQL خارجی، نسخهٔ client باید سازگار و مجوز ایجاد دیتابیس آزمایشیِ متعلق به پنل موجود باشد.

Restore پس از توقف نویسنده‌ها از وضعیت نهایی بکاپ می‌گیرد؛ شکست یا قطع عملیات به همان داده‌ها، کلیدها و تنظیمات برمی‌گردد. رمز مدیر، JWT، اتصال دیتابیس و secrets جاری حفظ می‌شوند و تنظیمات غیرمحرمانهٔ پشتیبانی‌شده بازیابی می‌شوند. PostgreSQL در دیتابیس تازه بازیابی می‌شود و دیتابیس قبلی حفظ می‌شود. فرمت قدیمی v1 نیز از همین موتور استفاده می‌کند، اما کلیدهایی که در بکاپ قدیمی وجود نداشتند قابل بازیابی نیستند.

`pvnetwork recover --yes` عملیات قطع‌شده را بازیابی می‌کند. `pvnetwork rollback --yes` کد قبلیِ سازگار را با حفظ دادهٔ جاری فعال می‌کند. تغییر schema بدون مسیر migration و restore جداگانهٔ تأییدشده رد می‌شود.

تست‌های واقعی محلی Update، Restore، Rollback، قطع با SIGKILL، بازیابی کلید رمزنگاری و حفظ PID سرویس نامرتبط گذشته‌اند. dump و restore واقعی ۲۷ جدول PostgreSQL 16 نیز با تمام hash ردیف‌ها برابر بوده است. تست دیتابیس CI از سرویس موقت و مجزا استفاده می‌کند و اثبات امنیت احراز هویت Production نیست. این سند نصب نود، منوی CLI، ACME عمومی یا ترافیک اینترنت آزمایش‌نشده را موفق اعلام نمی‌کند.
