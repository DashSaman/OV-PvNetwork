# نامزد v1.0.53 — PVN-1037

آماده‌سازی بکاپ بومی پیش از هر استقرار، لینک موجود کلید را رد کرد. فقط metadata بررسی شد: مسیر canonical کلید در `/etc/pvnetwork-panel` به همان فایل نام‌دار در `/etc/pvnetwork` اشاره می‌کند؛ فایل عادی متعلق به root با مجوز 0600 در پوشهٔ root با مجوز 0700 است. محتوای کلید چاپ، جابه‌جا یا بازتولید نشد.

سیاست بکاپ و بازیابی اکنون فقط همین لینک ثابت را می‌شناسد. مالک root برای لینک، مقصد و همهٔ والدها، نبود والد لینک‌شده/قابل نوشتن، پوشهٔ خصوصی و فایل عادی خصوصی با اندازهٔ محدود بررسی می‌شود. مسیر دلخواه، لینک شکسته یا هدایت‌شده رد می‌شود. بکاپ بایت فایل عادی را با نام منطقی فعلی v2 ذخیره می‌کند. بازیابی همان میزبان، مقصد تأییدشده را اتمیک می‌نویسد، پیش از جایگزینی لینک را دوباره بررسی می‌کند و خود لینک را حفظ می‌کند. رفتار فایل عادی canonical، دیتابیس و رابط تغییر نمی‌کنند.

ده آزمون POSIX با root، آرشیو و بازیابی واقعی، رمزگشایی Fernet، هویت لینک، فایل canonical، مقصد هدایت‌شده/لینک‌شده/حذف‌شده، مجوز/مالک ناامن و تغییر لینک پیش از بازیابی را بررسی می‌کنند. این‌ها در gate صریح root روی Linux CI اجرا می‌شوند. روی Windows هشت بررسی مرتبط آرشیو و نسخه موفق و موارد POSIX به‌همراه Bash لینوکس صریحاً اجرا نشده‌اند؛ این نتیجه PASS برای POSIX نیست. compile و lock جدا بررسی می‌شوند. CI پیاده‌سازی `7db59e1` در اجرای [38973202731](https://github.com/DashSaman/OV-PvNetwork/actions/runs/38973202731) موفق شد: ۷۲۶ تست کشف‌شده همراه gateهای مستقل root، امنیت، مرورگر و نصب تازه/تکراری واقعی systemd روی هر سه توزیع با SHA256 یکسان فایل منبع. بکاپ بومی، ۳۲ جدول PostgreSQL را واقعاً بازیابی و fingerprint کرد و شش فایل runtime و پنج checksum تأیید شدند. clone ایزوله پس از بازیابی و migration، health و فایل‌های UI نامزد را با موفقیت سرو کرد. تنظیمات، proxy و PID سرویس‌های محافظت‌شدهٔ زنده ثابت ماندند و Production روی ۱٫۰٫۴۰ است. این آماده‌سازی مجوز استقرار نیست؛ commit نهایی و نصب از دانلود رسمی هنوز بررسی دقیق جداگانه می‌خواهند.

این سازگاری بازیابی همان میزبان است و تأیید مهاجرت خودکار میزبان تازه نیست. کلید زنده، تنظیمات، سرویس، نود یا سطر مشتری تغییر نکرده‌اند. انتشار و استقرار محدود نهایی Production gate دارند. rollback کد، رد لینک قبلی را بازمی‌گرداند؛ بکاپ معتبر و ابزار بازیابی امن را نگه دارید.

بازیابی تأییدشدهٔ همان میزبان، مقصد قدیمی حذف‌شده یا خالی را نیز فقط در همان مسیر محافظت‌شده بازسازی می‌کند و لینک canonical حفظ می‌شود. بکاپ همچنان مقصد حذف‌شده یا خالی را رد می‌کند. برای این آزمون هیچ کلید عملیاتی تغییر نکرده است.

کانال manifest مقصد Stable موردنظر همین فایل تغییرناپذیر را مشخص می‌کند. وضعیت prerelease در GitHub همچنان gate انتشار است؛ انتشار QA به معنی نسخهٔ Stable پشتیبانی‌شده نیست. ارتقا به Stable باید همان tag و بایت‌های تأییدشده را حفظ کند و پس از gateهای مرتبط و مجوز محدود Production انجام شود. ACME عمومی، ARM و شبکهٔ VPS خارجی بدون زیرساخت لازم NOT TESTED هستند. workbench بومی امنیت روی منبع تغییرناپذیر v1.0.45 به علت reconciliation بسته‌نشدهٔ candidateها هنوز partial است؛ پنج یافتهٔ معتبر حفظ شده و اصلاحات آن‌ها در v1.0.46 و v1.0.50 قرار دارند. گواهی مستقل امنیتِ تکمیل‌شده ادعا نمی‌شود.
