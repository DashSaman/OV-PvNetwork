# PVN-1027 / 1.0.43 native node candidate

This is an implementation candidate, not a published stable release. Public stable remains 1.0.37 and authorized Production remains the verified 1.0.40 checkpoint. No new Production node, VPN, firewall or credential migration has been performed.

The controller creates a deterministic, source-only node bundle without reading an installed local node. The SSH bootstrap verifies its complete SHA256 before reading/executing the manifest-checked installer. Supported host/architecture, memory/disk, listeners, existing VPN state and subnet routes are checked before provisioning. Fresh and adopt are explicit modes. Password/private-key SSH authentication remains in memory and uses pinned host fingerprints or existing trusted host keys.

The native agent uses independent `pvnetwork-node` source/releases, private pinned uv/Python and a frozen dependency lock. API access is authenticated HTTPS; public documentation is disabled by default. Its CA arrives over verified SSH. An additive owned `node_tls_bindings` metadata table records CA/credential digests without plaintext credentials; database-native backups include it. It does not alter existing node/user columns or the existing migration head. Losing local CA files must not cause adopted, unchanged credentials to fall back to HTTP. Older code without this transport is refused for a rollback while live native nodes require it.

A short-lived deployment proof validates that the node can reach the controller actually issuing its SSH job. It does not expose an administrator token to a node. A wrong controller URL, CA or proxy must fail before package installation. The panel verifies authenticated node health, commits registration and separately finalizes the owned remote transaction. Failure before durable registration rolls back only the owned node installation. Job files are private and progress/errors exclude SSH material and node credentials; validation errors exclude input values.

Fresh OpenVPN uses signed distribution packages and EasyRSA, distinct API and VPN ports, a dedicated unprivileged VPN identity, protected local hook credentials and scoped tagged network rules. No firewall flush or policy replacement is used. OpenVPN's service uses cgroup task bounds instead of a per-UID process limit that can terminate it when hooks fork. Fresh TCP requires the server protocol variant. Reapplying identical settings must not restart OpenVPN.

Traffic accounting sums simultaneous sessions with integer RX/TX counters. A durable per-session SQLite ledger retains reconnect/disconnect totals and consumes final-byte samples from a protected spool. The final disconnect counters and connection timestamp follow the [OpenVPN 2.6 environment contract](https://build.openvpn.net/man/openvpn-2.6/openvpn.8.html). Central device leases refresh periodically; incomplete status files never become authoritative empty snapshots. A denied transport is resolved and terminated on the same management socket, avoiding client-ID reuse across a server restart.

Adopt preserves the existing node ID/name/key (including compatible keys longer than the fresh creation limit), assignments, compatible CA/profile PKI, configuration and OpenVPN PID. It requires a free new API port and a root-protected management socket. Recognized legacy session hooks are backed up privately with checksums, permissions and ownership before atomic aliases activate native hooks. Accounting is seeded from complete current status; hook credentials/spool use the existing VPN group. The old agent/collector are stopped and disabled only after controller registration. Foreign hooks, unverified services and operator changes are preserved for explicit migration. Existing-package upgrade/removal/reconfiguration is refused. Live node restore and general disaster recovery remain open.

Agent code upgrades stage a frozen immutable release, run an authenticated HTTPS canary without background workers, and switch only the agent pointer/service. Durable recovery and code rollback preserve live OpenVPN and current counters. Recovery accepts an already vanished owned transient canary after reboot; an existing service stop failure remains an error. Controller callbacks refuse redirects and environment proxies. Source bundles select explicit distributable files, excluding local runtime/environment backups.

Subsequent security checks reproduced submitted SSH material in the default HTTP 422 validation response; the controller now omits input/context and redacts sensitive custom messages. The authenticated demo HTTP regression passed. The first frozen-backend CI audit failed on three findings in PyJWT 2.14.0 and multidict 6.9.0; only those dependency packages were updated to PyJWT 2.15.1 and multidict 6.9.1, with the minimum JWT constraint raised. The new pinned audit found no known vulnerabilities, and ten authentication/CORS regressions passed against the frozen updated environment. Older candidate locks still require release audit/backport before publication.

Native preflight runs before creating installed state/locks and rejects an existing `pvn0` interface. Fresh/adopt package planning installs only missing packages and refuses upgrades/removals/reconfiguration of installed packages. API rules are inserted ahead of earlier ACCEPTs; owned VPN INPUT/FORWARD rules and API persistence precede agent startup. Rollback validates owned file digests before stopping services and stops its owned network unit. An isolated child network namespace exercised real iptables, repeated persistence, and earlier foreign ACCEPT/policy preservation without changing the parent node network. Exact final fresh boot/traffic and interruption verification of these later changes remain open. Native installation currently requires an IPv4 controller source; IPv6 native binding remains unverified and is rejected before mutation. Legacy IPv6 transport remains compatible.
