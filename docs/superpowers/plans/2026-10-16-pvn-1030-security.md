# PVN-1030: authorization and subscription push boundaries

Base: 1.0.45 / 659f30c307f95871db843697797430e6f0f98c8b.

The source audit established four concrete failures: reseller presence exposes
other owners' live-rate UUIDs; a read-scoped GET resets usage; public push accepts
arbitrary HTTPS destinations; duplicate test routes bypass the intended cooldown.

1. Reproduce tenant disclosure and read-token mutation through ASGI with real
   SQLite rows. Filter every presence map using the same owned UUID set. Make
   GET user detail read-only; move reset to POST and update both Web callers.
   Preserve reset accounting, unlimited renewal, ownership and mutation locks.
2. Reproduce public route dispatch and cooldown races. Consolidate the route,
   reserve a persisted cooldown atomically before outbound work, support old
   SQLite/PostgreSQL schemas and keep blocking delivery outside the event loop.
3. Share outbound push validation between registration and every sender. Permit
   supported public browser push origins and explicit operator HTTPS origins;
   reject ambiguous URLs, credentials, unsafe destinations and redirects, with
   environment proxies disabled. Exercise stored legacy rows as well as new input.
4. Review the complete diff and alternate inputs/callers. Run focused security
   and ordinary-control tests, full backend checks, frontend build/browser gates,
   frozen dependency audits and exact-commit CI before creating a reviewable PR.

The audit remains attached to its immutable 1.0.45 snapshot. No live credentials,
customer identifiers or private evidence belong in public artifacts. Production
deployment remains a separate scoped approval after a verified candidate exists.
