# PVN-1032 — supported database domain ingestion

The real collector route fails on a fresh SQLite schema because its PostgreSQL
named conflict target is rendered as a nonexistent SQLite column. The old table
also uses a BIGINT primary key, which SQLite does not generate as a rowid alias.

1. Keep an actual SQL regression for first/repeated batches, ownership, privacy,
   concurrent writers and the maximum 1,000-event payload. Confirm the baseline
   fails before changing implementation.
2. Select the supported database dialect's insert and scalar min/max functions.
   Preserve the unique user/node/domain conflict key and atomic hit increment.
   Assign SQLite IDs inside the INSERT statement under its writer lock, avoiding
   a separate racy Python max-ID lookup and any schema/table rewrite.
3. Verify transactional failure rollback and actual PostgreSQL merging in an
   owned disposable database. Keep all live data and nodes outside this work.
4. Update candidate metadata and bilingual notes, review the diff, run full
   regression and exact-commit CI, then create the next stacked candidate PR.

Public publication and Production approval remain separate mission gates.
