# PVN-1028 — Node archive workflow implementation plan

**Goal:** Complete the requested Web node backup/download and uploaded-file restore workflow using the verified native engines, without a terminal on the node.

**Architecture:** Extend the existing authenticated node workflow and pinned SSH transport. SSH credentials remain request-local; root-private bounded archives and sanitized operation receipts survive only as needed for download/recovery. Existing certificate, accounting, ownership and rollback guards remain authoritative.

**User specification:** Final completion mission, sections 2, 5, 6, 8, 9 and 13: preserve users/CA/UUID/accounting, explicit Fresh versus Adopt, SSH fingerprint verification, progress/errors/retry, configuration backup and restore, existing functionality, EN/FA and security. The user explicitly requested autonomous implementation and no repeated routine approval questions. This plan implements that authorized scope; it does not authorize Production mutations.

## Constraints

- Candidate 1.0.44 / PVN-1028; retain immutable earlier tags and the stacked dependency on native candidate 1.0.43.
- No new dependency/provider, unchecked download, shell interpolation of credentials, saved SSH password/private key, or secret-bearing job receipt.
- Main administrator only; validate node ID and operation scope before SSH; target comes from the registered node.
- Pinned SSH password or key authentication, existing trusted-host behavior, no automatic host-key replacement.
- Native source-only checked bundle; bounded binary SSH streams transfer regular root-private files, verify SHA256 and never accept an arbitrary remote/local path from the caller. A fixed root/passwordless-sudo helper keeps archives at mode 0600; SFTP alone cannot read those files for an approved non-root SSH user, so archive permissions must not be weakened for transport.
- Compatible restore is the default. Offline PKI recovery and starting recovered services require explicit UI choices and a scoped downtime confirmation. Existing engine protections against newer certificates/revocations/operator changes remain.
- Controller archive storage must be canonical/private, symlink-safe, bounded and time-limited; exported data is sensitive and is never included in the public source artifact.
- Reuse deployment host exclusion and sanitized progress/jobs. On timeout/interruption preserve the native durable transaction and give an actionable recovery result.

## Implementation

- [ ] Add transport tests first: pinned password/key, byte/size/SHA checks, root-private path/symlink guards, interrupted transfer cleanup, no secret output, compatible/offline flags and failure preservation.
- [ ] Implement focused `backend/node/archive_transport.py` using existing `native_deploy.connect/execute` and checked source bundle, plus a small standalone root stream helper; root-side operation and transfer scope must be fixed.
- [ ] Add private archive store and receipt tests: identity binding, traversal/symlink refusal, TTL/size/free-space, download authorization, upload limits, cleanup without customer deletion.
- [ ] Implement a focused node archive router and include it under the existing node API. Validate main-admin/node ownership before creating jobs or connecting. Keep SSH secrets out of persistent job dictionaries, retries and logs.
- [ ] Add API tests: unauthorized/reseller/missing node refusal, request validation privacy, real SQLite node binding, backup-download integrity, uploaded compatible restore, explicit offline/start flags and sanitized failures.
- [ ] Add a reusable EN/FA node archive modal linked from node management. Keep credentials in component memory, clear them on completion/close, show progress/health/receipt and actionable failure/retry. Warn that downloads contain private keys/settings.
- [ ] Browser-test real controls, upload/download and request bodies in both directions at the required nine widths; retain all 13 locales. Add actual owned SSH/TLS/native backup and restore tests, including existing-client preservation where feasible.
- [ ] Advance the coherent version metadata and task registry to candidate 1.0.44, update bilingual notes/docs, run relevant full CI/audits, create/attach the stacked draft PR. No public stable claim or Production deployment before their separate gates.

## Review focus

1. A malicious archive/path or symlink must fail before a remote write or service stop.
2. A request for node A must not export/restore node B's archive, even after rename, retry or controller restart.
3. Network loss or controller failure must not erase the last verified backup, customer PKI or current accounting.
4. A stale archive must not revive revoked users, reset counters, replace current credentials or bypass configuration-operation exclusion.
5. Reseller/browser/API error paths must not expose SSH credentials, node keys, archive bytes or root-private filesystem diagnostics.

## Separate gates

Final exact-source OS installs, restored-client handshake, all other Web controls and existing feature regressions, the 25-menu CLI, full UI/privacy/history/assets/docs, public release assets and owner-authorized Production remain tracked by the overall mission. Cold restoration onto a different host is a documented separate capability, not an inferred new requirement that blocks the requested same-node restore workflow.
