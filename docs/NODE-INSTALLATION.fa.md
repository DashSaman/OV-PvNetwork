# افزودن و بررسی نود PVNetwork

[English](NODE-INSTALLATION.md) · [راهنمای وب](UI-GUIDE.fa.md#4-nodes)

![فرم نصب نود](images/v1.0.54/fa/desktop/node-create.png)

## ۱. مقصد و اعتماد SSH

1. Ubuntu/Debian پشتیبانی‌شده، منابع، دسترسی root مجاز و وضعیت واقعی میزبان را بررسی کنید. میزبان دارای VPN یا تونل، نود خالی نیست.
2. پورت‌ها، تنظیمات VPN، سرویس‌ها، subnet/route و فایروال را بخوانید. پیش از پذیرش صریح نود موجود، بکاپ خصوصی بگیرید.
3. fingerprint نوع SHA256 کلید میزبان SSH را از کنسول یا مسیر مستقل مورداعتماد بگیرید. فرم از آن یا کلید قبلاً مورداعتماد استفاده می‌کند؛ صرفاً برای ادامه fingerprint تغییرکرده را قبول نکنید.
4. نود باید origin واقعی HTTPS همین controller را ببیند و پنل باید به پورت HTTPS API نود برسد. origin مانند `https://panel.example.com` و بدون path پنل است؛ `.example` مقدار نمونه است.

## ۲. نصب خودکار SSH

1. در **مدیریت نودها ← افزودن نود** حالت خودکار SSH را نگه دارید و نام، آدرس، پورت/کاربر SSH و رمز یا کلید خصوصی بدهید. اطلاعات حساس را در Git یا issue نگذارید.
2. **سرور تازه** فقط برای مقصد خالی واجد شرایط است. **پذیرش نود موجود** فقط برای نود ثبت‌شده سازگار است؛ ID موجود را بدهید و نام، آدرس، پورت و پروتکل VPN را حفظ کنید. این حالت پورت تازه آزاد HTTPS API و management/PKI محافظت‌شده سازگار لازم دارد؛ hook یا وضعیت ناشناخته ممکن است رد شود.
3. پورت API، پورت/پروتکل VPN، آدرس تونل، origin HTTPS کنترل‌کننده و fingerprint را بخوانید. API و VPN کاربرد جدا دارند و نباید پورت متداخل داشته باشند. IP مبدأ پنل اختیاری است؛ فقط وقتی مبدأ SSH با مبدأ مدیریت لازم فرق دارد، مثلاً NAT، مقدار درست را آگاهانه وارد کنید.
4. یک بار ثبت کنید. job را در بررسی checksum/proof، preflight، نصب، سلامت HTTPS احرازهویت‌شده، ثبت و finalization دنبال کنید. بسته شدن نمایش پیشرفت، پایان job پایدار را ثابت نمی‌کند.
5. پس از نتیجه نهایی موجودی را تازه کنید. در شکست، پیش از ارسال مجدد وضعیت job/recovery را بخوانید؛ تنظیمات نود زنده را پاک نکنید.

پنل بسته نود سازگار را از سورس بررسی‌شده ریپو می‌سازد و اعتماد SSH، یکپارچگی سورس و proof کوتاه‌عمر controller را بررسی می‌کند. وضعیت زنده ناسازگار رد می‌شود. [محدودیت‌ها و شواهد نود native](NODE-CANDIDATE.fa.md) به‌ویژه تفاوت fresh/adopt را بخوانید.

## ۳. ثبت دستی

1. حالت دستی فقط برای نود سازگار از قبل آماده‌شده است.
2. هویت، آدرس/پورت/کلید مدیریت، endpoint/protocol VPN و سایر فیلدهای لازم را درست وارد کنید.
3. API را از پنل و transport/binding ثبت‌شده را بررسی کنید. ثبت دستی VPN یا CA نصب نمی‌کند و HTTP دلخواه را خودکار به HTTPS native مورداعتماد تبدیل نمی‌کند.
4. پیش از تخصیص مشتری آزمون بعد را انجام دهید.

## ۴. آزمون مسیر کامل

![موجودی نود](images/v1.0.54/fa/desktop/nodes.png)

1. سلامت احرازهویت‌شده، نسخه و metrics نود را ببینید؛ پاسخ HTTP سبز به‌تنهایی کافی نیست.
2. کاربر ساختگی روی همان نود بسازید و پروفایل بگیرید. remote/protocol و وجود مواد خصوصی گواهی/کلید را بررسی کنید اما فایل را منتشر نکنید.
3. پروفایل را در کلاینت سازگار وارد، TLS/TUN را کامل و ترافیک واقعی از تونل عبور دهید. UDP/TCP را فقط وقتی هرکدام عمداً تنظیم شده‌اند تست کنید.
4. مصرف عدد صحیح و حضور را در پنل ببینید. disconnect/reconnect و ثبات مصرف و در صورت نیاز محدودیت هم‌زمان دستگاه را بسنجید.
5. حساب تست را غیرفعال کنید و قطع همان هدف و ادامه کار حساب تست دیگر را ببینید. حفظ سرویس‌ها، route و سیاست فایروال نامرتبط و در adopt حفظ هویت/PID VPN جاری را کنترل کنید.

## ۵. نگهداری و بازیابی

پیش از نگهداری موردنظر drain کنید و job تعمیر/همگام‌سازی محدود را تا نتیجه تأییدشده ببینید. ارتقای کد agent با ساخت دوباره VPN فرق دارد. [آرشیو نود](NODE-ARCHIVES-CANDIDATE.fa.md) روند بکاپ/Restore/recovery را دارد. برای دور زدن خطا یا کنترل آخرین نود، نود فعال را حذف و دوباره نسازید.
