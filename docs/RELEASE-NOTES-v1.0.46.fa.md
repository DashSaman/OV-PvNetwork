# نامزد v1.0.46 — PVN-1030

پاسخ presence و داشبورد نماینده اکنون فقط UUID کاربران خودش را نشان می‌دهد؛
این محدودیت روی پاسخ تازه و cacheشده اعمال می‌شود و cache عمومی مدیر اصلی را
تغییر نمی‌دهد. داشبورد نماینده و دسترسی کامل مدیر اصلی حفظ شده‌اند.

GET جزئیات کاربر فقط‌خواندنی است. اتصال‌هایی که با GET مصرف را reset می‌کردند
باید از `POST /api/users/{uuid}/reset` با مجوز `users:write` استفاده کنند.
هر دو عمل reset در وب اصلاح شده‌اند. تشخیص کاربر انتخابی در CLI از مسیر مستقل
`GET /api/users/{uuid}/sessions` استفاده می‌کند تا پس از rollback به backend قدیمی
نیز ناخواسته reset انجام ندهد. baseline مصرف، تمدید نامحدود و قفل تغییر حفظ می‌شوند.

ثبت و ارسال Web Push از کنترل مشترک مقصد استفاده می‌کنند. سرویس‌های Google،
Mozilla و زیردامنه‌های Push متعلق به Apple و Windows پشتیبانی می‌شوند. برای
سرویس دیگر، اپراتور origin دقیق HTTPS را بدون مسیر یا اطلاعات ورود در
`PUSH_ALLOWED_ORIGINS` محیط خصوصی پنل ثبت می‌کند. مقصد باید فقط به IP عمومی
resolve شود؛ اتصال به IP بررسی‌شده با صحت‌سنجی نام اصلی گواهی TLS انجام می‌شود.
redirect، پراکسی محیط، retry خودکار و خواندن نامحدود پاسخ غیرفعال‌اند. رکوردهای
ذخیره‌شدهٔ قدیمی نیز پیش از ارسال دوباره بررسی می‌شوند.

مسیر تست Push یکتا است و پیش از ارسال، سهمیهٔ یک‌ساعتهٔ هر کاربر را اتمیک ثبت
می‌کند؛ شکست ارسال یا تغییر endpoint سهمیه را بازنشانی نمی‌کند. ارسال خارج از
حلقهٔ اصلی وب و با حداکثر چهار ارسال هم‌زمان تست در هر فرایند انجام می‌شود.
جدول سازگار جدید در SQLite و PostgreSQL به ستون اختیاری نسخه‌های قدیمی وابسته
نیست. UUID اشتراک و متن خام خطای سرویس در لاگ فرستنده نوشته نمی‌شوند.

آزمون‌های HTTP واقعی، جداسازی cache، رقابت SQLite/PostgreSQL، رمزنگاری واقعی
Web Push و VAPID با انتقال کنترل‌شده و regression وب انجام شده‌اند. CI همان commit،
بستهٔ عمومی نهایی و استقرار Production gateهای جدا دارند؛ انتشار نهایی تأیید نشده است.
