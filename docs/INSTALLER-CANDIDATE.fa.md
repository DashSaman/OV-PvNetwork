# راهنمای Candidate نصب — PVN-1025

این پیاده‌سازی در حال اعتبارسنجی است و release پایدار عمومی نیست. دستور نصب عمومی فقط پس از ایجاد و بررسی مجدد Artifact رسمی و عبور از gateها ارائه می‌شود.

پیش‌بررسی Ubuntu 22.04/24.04 و Debian 12، معماری x86_64/aarch64، حداقل ۱ GiB RAM و ۳ GiB فضای آزاد را بررسی می‌کند. پورت اشغال، نصب یا سرویس/site پنل موجود و دیتابیس غیرخالی رد می‌شوند. نصب مجدد همان بستهٔ کامل فقط سلامت را بررسی می‌کند؛ hash متفاوت با همان نسخه پذیرفته نمی‌شود. معماری تست‌نشده PASS محسوب نمی‌شود.

Bootstrap بستهٔ ثابت رسمی و SHA256 آن را دریافت و hash، مسیرها، نوع اعضا، اعضای تکراری، اندازه و metadata نسخه را بررسی می‌کند. ابزارهای uv/Node/Python با نسخه و hash ثابت در مسیر اختصاصی نصب می‌شوند؛ ابزارهای پروژه‌های دیگر جایگزین نمی‌شوند. وابستگی‌های برنامه از lock و بسته‌های سیستم از مخزن امضاشده نصب می‌شوند. cache اختیاری `PVNETWORK_TOOL_CACHE` نیز باید همان hashهای معتبر را داشته باشد.

برنامه ابتدا در مسیر release جدا ساخته و سپس مسیر پنل به‌صورت اتمی به آن متصل می‌شود. فایل محیطی و داده در مسیر مشترک خصوصی می‌مانند. اطلاعات ورود در `/etc/pvnetwork-panel/initial-credentials.txt` با دسترسی 600 ذخیره می‌شود و در log چاپ نمی‌شود.

Setup Mode پیش‌فرض فقط روی `127.0.0.1:18443` است. از SSH forwarding رمزگذاری‌شده استفاده کنید: `ssh -L 18443:127.0.0.1:18443 USER@SERVER`. URL اعلام‌شده `http://127.0.0.1:18443/panel/` عمومی نیست. برای HTTPS روی سرور تازه، دامنه و ایمیل واقعی، پورت‌های آزاد 80/443، DNS صحیح و دسترسی ACME لازم‌اند. تا صدور گواهی، HTTP فقط challenge را پاسخ می‌دهد و سایر درخواست‌ها 503 می‌گیرند. HTTPS فقط بعد از تأیید certificate، proxy، سلامت و UI اعلام می‌شود. Installer برای حل مشکل ACME فایروال را تغییر نمی‌دهد.

دیتابیس خالی با schema و constraintهای جاری ساخته و revision نهایی ثبت می‌شود. SQLite در فایل جدا ساخته و پس از بررسی integrity به‌صورت اتمی فعال می‌شود. در PostgreSQL ساخت جدول‌ها و ثبت revision در یک تراکنش انجام می‌شود؛ شکست آزمایشی هیچ جدولی باقی نمی‌گذارد. migrationهای تاریخی تغییر نمی‌کنند و مسیر ارتقای دیتابیس موجود هستند. نصب تازه جایگزین ارتقا یا پذیرش دیتابیس موجود نیست.

journal خصوصی و lock مشترک مراحل نصب را ثبت می‌کنند. `--recover` فقط نصب شکست‌خورده یا قطع‌شدهٔ همان نسخه و hash را بازیابی می‌کند؛ فقط فایل‌ها، pointer و سرویس‌های متعلق به آن عملیات بازگردانده می‌شوند و داده/Secrets حفظ می‌شوند. نصب دوباره، مجوز پاک‌کردن دیتابیس یا deployment موجود نیست.

تست‌های اجرایی Linux پذیرش checksum اشتباه، نسخهٔ اشتباه و symlink توسط نسخهٔ قبلی را بازتولید کردند. تست‌های تازه constraintها، حفظ دیتابیس موجود، شکست اتمی schema، پورت، پیش‌بررسی، HTTP پیش از TLS و وضعیت recovery را پوشش می‌دهند. محیط‌های موقت با systemd واقعی برای نصب و سرویس‌ها استفاده می‌شوند؛ fixture جای تست واقعی معرفی نمی‌شود. ACME عمومی، اتصال خارجی، ماتریس معماری، lifecycle و ترافیک نود gateهای جدا هستند و بدون اجرای واقعی PASS اعلام نمی‌شوند.

اصلاح استخراج امن ابزار: آرشیو رسمی Node با محدودیت موجودی در staging خصوصی استخراج می‌شود؛ traversal، عضو تکراری و والد symlink رد و پوشه اتمیک منتشر می‌شود. خروجی ناقص timeout در لاگ خصوصی 0600 حفظ می‌شود؛ خطا آرگومان حساس را نشان نمی‌دهد. سلامت فقط HTTPS یا HTTP متعلق به loopback را می‌پذیرد و CI ممیزی static نصب‌کننده را اجرا می‌کند. import جاافتادهٔ SecuritySettings در نگه‌داری بکاپ با تست اجرایی اصلاح شد. CI دقیق و نصب روی توزیع‌ها همچنان لازم‌اند.

Snapshot مستقل سورس در لینوکس: ۴۱۶ تست، ۴۱۳ پاس و سه skip ویژهٔ PostgreSQL؛ ممیزی متوسط/بالای backend و نصب‌کننده پاس است. فایل‌های باقی‌ماندهٔ تصویر پایه وارد snapshot نشده‌اند.
