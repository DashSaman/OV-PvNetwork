# کنسول عملیاتی PVNetwork — نامزد 1.0.45

با `sudo pvnetwork` منوی ۲۵ گزینه‌ای باز می‌شود. `--lang fa` و `--lang en` زبان را انتخاب می‌کنند؛ گزینهٔ ۲۴ ترجیح زبان را در فایل خصوصی ذخیره می‌کند. راهنمای هر فرمان با `--help` در دسترس است. اجرای غیرتعاملی باید فرمان مشخص داشته باشد.

گزینه‌ها به‌ترتیب: وضعیت، سرویس‌ها، نودها، کاربران/نشست‌ها، لاگ، عیب‌یابی، Doctor، ترمیم محدود، به‌روزرسانی، بکاپ، بازیابی، بازگشت نسخه، TLS، نشانی/پورت/مسیر پنل، اطلاعات ورود مدیر، فایروال، شبکه، Nginx، دیتابیس/مهاجرت‌ها، منابع، کارهای پس‌زمینه، نسخه، بستهٔ پشتیبانی، زبان و خروج.

هر تغییر `--dry-run` دارد؛ این حالت فقط عملیات انتخاب‌شده را نشان می‌دهد و سرویس، فایل یا دیتابیس را تغییر نمی‌دهد. تغییرات به root و تأیید `YES` یا `--yes` نیاز دارند؛ بکاپ، بستهٔ پشتیبانی و ذخیرهٔ زبان تأیید اضافه ندارند. فرمان سرویس فقط پنل و timerهای مشخص پروژه را می‌پذیرد.

```sh
sudo pvnetwork --lang fa
sudo pvnetwork doctor --json
sudo pvnetwork services restart --unit pvnetwork-panel.service --dry-run --json
sudo pvnetwork repair --scope node-reconcile --node-id 7 --yes --json
sudo pvnetwork nodes job --node-id 7 --job-type reconcile --job-id <returned-job-id> --json
sudo pvnetwork nodes job --job-type deploy --job-id <returned-job-id> --json
sudo pvnetwork database check --json
sudo pvnetwork support --output /root/pvnetwork-support.tar.gz --json
sudo pvnetwork recover --yes --json
```

بکاپ، update، restore و rollback از موتور بومی موجود با قفل و بررسی بازیابی استفاده می‌کنند. update فقط نسخهٔ منتشرشدهٔ تغییرناپذیر و SHA256 همان asset را می‌پذیرد. branch نامزد قابل استفاده به‌عنوان انتشار عمومی نیست. شکل JSON قدیمی فرمان‌های چرخهٔ عمر، نسخه و وضعیت حفظ شده است.

رمزها در ترمینال مخفی دریافت می‌شوند. اتوماسیون، JSON محدود را با `--input-json-stdin` از منبع خصوصی می‌گیرد؛ رمز، کلید و توکن را در آرگومان، history یا لاگ عمومی ننویسید. کلاینت فقط با API ثابت loopback ارتباط می‌گیرد؛ proxy و redirect غیرفعال است و توکن کوتاه‌عمر چاپ نمی‌شود.

`settings apply` رمز فعلی مدیر و `new_path` یا `new_port` را می‌پذیرد. `credentials apply` برای نام کاربری یا رمز جدید است. پورت داخلی باید آزاد و بین ۱۰۲۴ تا ۶۵۵۳۵، به‌جز ۱۹۰۰۲ باشد. listener عمومی HTTPS و فایروال حفظ می‌شوند. build و canary پیش از تعویض اجرا می‌شوند؛ env، build و پراکسی قبلی برای بازگشت نگه داشته می‌شوند. `recover` تغییر قطع‌شده را بازیابی می‌کند و تغییر ناشناختهٔ اپراتور را بازنویسی نمی‌کند. بازگشت تأییدنشده در وضعیت `recovery_required` باقی می‌ماند.

ترمیم نود فقط پروفایل‌های همان ID را بررسی می‌کند؛ تخصیص کاربران، drain و وضعیت سرویس VPN حفظ می‌شوند. ویرایش بدون کلید جدید، کلید ذخیره‌شده را حفظ می‌کند. تغییر نام نودی که هویت کاربران به آن وابسته است رد می‌شود، چون CN فعلی پروفایل نام نود را دارد. حذف نود از محافظ‌های تخصیص کاربران و آخرین نود استفاده می‌کند. [راهنمای بکاپ نود](NODE-ARCHIVES-CANDIDATE.fa.md) الزامات SSH معتبر و بازیابی آفلاین را توضیح می‌دهد.

`tls renew` فقط cert-name گواهی ACME متعلق به سایت مدیریت‌شدهٔ پنل را انتخاب می‌کند؛ تمدید اجباری ندارد. پس از بررسی Nginx، reload آرام انجام می‌شود. بررسی دیتابیس فقط خواندنی و زمان‌دار است. بستهٔ پشتیبانی فقط اطلاعات ساختاری مجاز دارد؛ فاقد لاگ خام، تنظیمات و اطلاعات مشتریان است و با مجوز 0600 در پوشهٔ خصوصی ساخته می‌شود.

کد خروج: ۰ موفق، ۶۴ آرگومان نامعتبر، ۶۹ ناسالم/در دسترس نیست، ۷۰ خطای عملیات، ۷۵ مشغول/نیازمند بازیابی، ۷۷ نیازمند root/تأیید، ۱۳۰ قطع‌شده. پاسخ صف به‌معنای پایان موفق نیست؛ وضعیت نهایی کار را بررسی کنید.

این نسخه هنوز نامزد است. شواهد فعلی شامل ۶۸۰ تست Linux با ۴ مورد PostgreSQL اجرا‌نشده، پیمایش واقعی ترمینال فارسی/انگلیسی و ماتریس‌های ۱۸ حالتهٔ مرورگر برای ترمیم نود، بکاپ، ویرایش و تغییر پورت است. CLI نصب‌شده در systemd، حفظ env/دیتابیس/PID توسط Doctor، مجوز خصوصی پشتیبانی، زبان ذخیره‌شده و رفت‌وبرگشت واقعی پورت با رمز فعلی مدیر را گذراند. worker مستقل و Node پین‌شده استفاده می‌شوند. artifact و CI سورس نهایی، کنترل‌های کامل مأموریت، asset عمومی و استقرار مجاز Production همچنان gate انتشار هستند.
